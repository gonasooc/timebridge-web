# UI 디자인 기준

2026-10-02 코칭 시안을 구현하고 같은 날 사용자 레퍼런스·폰트 요청을 반영한 기준이다. 상품 범위는 [docs/plan.md](plan.md), 화면 검증 결과는 [docs/work/W-002-main-coaching-mvp.md](work/W-002-main-coaching-mvp.md)에서 관리한다. 종이색·자주색 유지와 Pretendard 통일은 사용자 요청이다. 세부 화면과 문항은 시안 검토로 조정할 수 있다.

## 디자인 맥락과 원본

커뮤니티·SNS에서 유입된 성인 자녀가 휴대폰으로 부모님 인터뷰의 결과물을 이해하고, 자신에게 맞는 진행 방향을 선택한다. 다정하고 담백한 문장을 쓰며 가족에 대한 죄책감·가짜 후기·임박한 마감을 이용하지 않는다.

- [PRODUCT.md](../PRODUCT.md): 사용자와 디자인 원칙.
- [DESIGN.md](../DESIGN.md): 도구가 정본 문서를 찾는 연결점.
- [src/coaching.css](../src/coaching.css): 코칭 UI의 색·레이아웃·컴포넌트 원본.
- [src/styles.css](../src/styles.css): 공통 초기화·기본 글꼴·어절 줄바꿈·모션 감소.
- [index.html](../index.html), [src/main.js](../src/main.js): 화면 구조와 상호작용.
- [src/sample-data.js](../src/sample-data.js): 가상 인물·주제별 질문·피드백.

이전 무료 앱의 녹색 테마·정책 화면·디자인 설명은 교체했다. 앱 테마와 자동 동기화하거나 400·500 굵기만 사용해야 한다는 과거 규칙은 승계하지 않는다.

## 관찰된 시각 구현

종이색 배경과 자주색 강조의 핵심 OKLCH 값은 유지했다. 정확한 값은 원본 CSS에서 관리한다. 제목·본문·대화 기록·입력·숫자까지 모두 Pretendard를 사용한다. 고운바탕과 Google Fonts 로드는 제거했다. 외부 폰트를 사용할 수 없으면 로컬 한국어·시스템 글꼴로 표시한다.

소개는 비대칭 두 열을 유지하고, 기울어진 종이와 겹친 메모를 정렬된 가상 기록 미리보기로 교체했다. 실제 책·고객 기록이나 동작하는 녹음 앱처럼 표시하지 않는다. 모바일에서는 소개 문구 뒤에 가상 기록을 놓는다.

제목은 600~650 수준의 굵기와 본문의 400~550을 대비한다. 제목의 자간·줄 간격을 정돈하고 본문 길이는 제한한다. 주요 패널은 20~30px, 컨트롤은 10~12px 모서리를 사용하며 얇은 경계선과 약한 그림자로 표면을 구분한다. 네 화면의 버튼·입력·포커스는 같은 기준을 사용한다.

단계 표시는 현재 단계가 자주색으로 채워지는 묶음형 탐색이다. 선택과 상담은 밝은 입력 면에 묶고 질문 간 여백으로 구분한다. 가격 안내는 모서리가 둥근 자주색 섹션이며, FAQ와 과정은 패널을 반복하지 않고 정렬과 구분선으로 구성한다.

사이트는 종이 기록의 인상을 유지하는 밝은 테마다. OS의 다크 설정에서도 같은 밝은 팔레트를 사용한다. 별도 다크 테마는 구현하지 않았다.

## 화면과 상호작용

| 화면 | 구현과 확인할 상태 |
| --- | --- |
| 소개 | 상품 범위·가격·진행 과정·FAQ, 미리보기 CTA, 체험용 안내 |
| 방향 선택 | 필수 라디오 세 그룹, 선택 체크박스, 미선택 오류, 선택값 유지 |
| 샘플 | 선택 요약·수정 링크, 질문 6개와 기억 질문, 인터뷰 목표 2개, 고정 가상 인물·전사·코치 피드백 |
| 상담 | 필수 이름·이메일·시기·방식·참여 의향, 오류, 초안 표시·수정·지우기 |

출생 연대와 주제에는 모른다는 선택지를 제공한다. 주제 미정이면 어린 시절의 장소·사람에서 시작하는 예시임을 안내한다. 대상이 아버지여도 전사 예시는 가상 인물 이정희와 딸의 이야기로 유지하고, 선택한 부모님과 별개인 예시임을 가까이 표시한다.

방향에 따른 질문과 실제 코칭으로 받을 맞춤 질문 40개를 구분한다. 상담 버튼은 ‘작성 내용 확인하기’이며 초안에 미접수 상태를 명시한다. 결제·서버 저장·전사의 가짜 로딩이나 성공 상태는 만들지 않는다.

## 반응형·접근성

- 최대 콘텐츠 폭은 1160px. 1050px·760px·360px 기준으로 열·여백·글자 크기를 조정한다.
- 선택·상담은 데스크톱에서 설명과 폼을 두 열로, 모바일에서 한 열로 표시한다. 샘플 계획 영역도 모바일에서는 기록 아래에 놓는다.
- 실제 라디오·체크박스·fieldset·legend·label을 사용한다. 필수 오류는 텍스트와 `aria-describedby`, `aria-invalid`로 연결한다.
- 첫 제출 전에는 오류를 보이지 않는다. 제출 실패 시 첫 누락 항목으로 포커스를 이동하고, 이후 수정 시 오류를 갱신한다.
- 단계 이동 시 현재 제목으로 포커스를 옮긴다. 본문 건너뛰기는 현재 화면을 유지한다. 키보드 포커스는 자주색 외곽선으로 표시한다.
- 입력 글자는 16px이며 선택 영역과 주요 버튼에는 충분한 높이를 둔다. 보조 행동 링크도 최소 44px 높이로 누를 수 있게 한다. 단계 표시와 선택 체크박스는 40px 이상의 조작 영역을 둔다.
- FAQ는 native details/summary로 열고 닫는다. 홈 진입 모션과 hover 이동은 모션 감소 환경에서 끈다.
- JavaScript가 없으면 체험 불가 안내를 표시하고 제출 버튼을 비활성화한다. 폼 기본 제출도 전송되지 않도록 구성한다.

## 검증 범위와 남은 확인

Playwright로 데스크톱 Chromium과 모바일 Chromium 에뮬레이션을 검증한다. 자동 검사는 전체 흐름, 필수 입력, 주제 전환, 뒤로 가기·새로고침, 가상 표시, 연락처 비전송·비저장, 키보드 초점과 가로 넘침을 다룬다. 실제 실행 결과와 화면 확인 범위는 작업 문서에 기록한다.

Safari·실물 휴대폰·스크린리더 전수 점검은 미실행이다. 실제 접수 도입 뒤에는 저장 중·저장 실패·재시도·중복 제출·접수 완료와 실제 수집 안내를 별도로 구현하고 확인해야 한다.
