# 타임브릿지 코칭 MVP 개발 계획

커뮤니티와 SNS에서 유입된 자녀가 샘플을 확인하고 상담을 거쳐 9.9만원 코칭을 구매하는 웹을 만든다. 첫 목표는 유료 5가구 모집과 운영 가능성 검증이다. 이 문서는 2026년 10월 2일 대화에서 합의한 제품 범위와, 이를 구현하기 위한 작업 제안을 구분해 기록한다.

현재 저장소는 가상 샘플을 포함한 네 화면의 내부 시안을 구현했다. 코칭 신청 저장, 결제 확인, 전환 계측은 아직 구현되지 않았다. 구현 결과와 검증은 [docs/work/W-002-main-coaching-mvp.md](work/W-002-main-coaching-mvp.md)에서 관리한다.

## 합의한 제품 범위

| 항목 | 결정 |
| --- | --- |
| 첫 상품 | 9.9만원 유료 베타, 동시 5가구, 8주 코칭 |
| 제공 범위 | 상담 3회, 맞춤 질문 40개, 인터뷰 2회, 총 2시간의 검수된 전사본 |
| 역할 | 자녀가 부모님을 인터뷰하고 운영자가 준비와 피드백을 제공 |
| 기본 전사본 | 말한 순서 유지, 화자 구분, 사람이 전사 오류 확인, 불명확한 부분 표시 |
| AI 사용 | 당사자 동의와 보안 조건 확인을 전제로 AI 전사 허용, 사람이 검수 |
| 편집 범위 | 주제별 재구성과 윤문은 선택형 책 제작 단계에 포함 |
| 공개 샘플 | 가상 인물과 더미 데이터로 구성, 실제 고객 사례로 소개하지 않음 |
| 모집 | 직접 접근 가능한 커뮤니티와 SNS |
| 운영 | 창업자가 직접 코칭, 초기 상담과 결제 확인은 기존 수단 이용 |

AI 전사 허용은 기존 mochang 문서의 AI 입력 금지 원칙을 이번 대화에서 변경한 결정이다. 요약·해석·원고화까지 허용한 것으로 확대하지 않는다. 제출 이력인 `apply.md`는 당시 원문으로 보존하고, 후속 구현에서는 이 결정과 실제 채택한 처리 방식을 기준으로 안내한다.

## 첫 구현에서 보여줄 흐름

소개 → 방향 선택 → 맞춤 샘플 → 상담 신청

| 화면 | 내용 | 다음 행동 |
| --- | --- | --- |
| 소개 | 자녀가 할 일, 운영자의 도움, 기간과 가격, 질문지와 전사본 예시, 책 별도 안내 | 우리 부모님 인터뷰 미리보기 |
| 방향 선택 | 대상, 출생 연대, 관심 주제, 걱정되는 점 | 맞춤 진행 예시 보기 |
| 맞춤 샘플 | 선택에 맞는 질문 5~8개, 두 인터뷰의 목표, 가상 전사본과 코칭 피드백 | 이 방식으로 상담하기 |
| 상담 신청 | 연락처, 가능한 일정, 대면·전화·영상통화 중 가능한 방식, 부모님 참여 의향 | 신청 저장 후 접수 확인 |

방향 선택에는 이름과 연락처를 요구하지 않는다. 입력값에 따라 준비한 질문과 진행 안내를 조합한다. 가상 전사본은 특정 가상 인물의 예시로 표시하며 고객 부모님의 답변인 것처럼 생성하지 않는다.

구체적인 문항과 필수 여부는 구현 제안이다. 출생 연대와 관심 주제에는 `잘 모르겠어요`를 제공한다. 두 분을 함께 기록하려는 경우에는 상담에서 제공 범위를 확인한다.

## 가상 샘플 제작

첫 시안에는 가상 인물 한 명의 일관된 사례를 만든다. 초기 주제는 어린 시절, 일과 선택, 자녀를 키우던 시절의 세 가지를 제안한다. 여러 페르소나와 대량 콘텐츠를 먼저 만들 필요는 없다.

- 인물 소개에는 가상 이름, 출생 연대, 살아온 곳, 직업, 가족관계를 설정한다.
- 주제별 질문 예시와 인터뷰 1회차·2회차의 목표를 준비한다.
- 대화 순서와 화자 표기를 유지한 짧은 전사 예시를 만든다.
- 불명확한 구간의 표시 방식과 후속 대화를 돕는 코칭 피드백을 보여준다.
- 샘플 가까이에 `가상 인물로 구성한 서비스 이용 예시입니다`를 표시한다.

가상 사례로 실제 고객 후기, 전사 정확도, 운영 시간, 완주율을 주장하지 않는다. 더미 전사본은 실제 음성인식 결과가 아니므로 전사 도구의 성능 근거로 사용하지 않는다.

## 개발 순서와 완료 기준

### 첫 단계는 화면과 샘플

기존 색상·타이포·공용 요소를 참고해 소개부터 상담 입력까지 이어지는 화면을 만든다. 현재 정적 웹 구조에서 시작하며 프레임워크 교체를 선행 작업으로 잡지 않는다.

- [x] 새 상품의 소개 문구와 FAQ, 가상 샘플 한 세트를 작성한다.
- [x] 네 화면을 연결하고 이전 단계로 돌아가도 선택값이 유지되게 한다.
- [x] 주제 선택에 따라 질문과 인터뷰 목표가 달라지게 한다.
- [x] 샘플의 가상 표시와 9.9만원 상품의 포함 범위를 일관되게 보여준다.
- [x] 모바일, 키보드 조작, 필수 입력 누락 상태를 확인한다.
- [x] 실제 접수 기능 연결 전에는 내부 시안으로 표시하고 개인정보 전송을 막는다.

완료 기준은 모바일에서 전체 흐름을 직접 체험하고, 샘플과 실제 구매 결과물의 관계를 이해할 수 있는 것이다. 이 단계는 화면 검토용이며 모집용 공개 완료를 뜻하지 않는다.

### 두 번째 단계는 실제 신청과 계측

공개 모집 전에 신청을 저장할 곳, 운영자가 확인할 곳, 회신 채널을 정하고 연결한다. 공급자와 호스팅은 아직 확정하지 않았다. 기존의 수동 운영 방식으로 5가구를 관리할 수 있으면 별도 관리자 앱은 만들지 않는다.

- [ ] 상담에 필요한 연락 수단 하나와 최소 신청 정보를 저장한다.
- [ ] 서버에서도 입력을 검증하고, 저장소 비밀키를 브라우저 코드에 포함하지 않는다.
- [ ] 운영자가 신청과 앞선 선택값을 함께 확인할 수 있게 한다.
- [ ] 저장 성공을 확인한 뒤에만 접수 완료와 접수 식별자를 보여준다.
- [ ] 실패 시 입력을 유지하고 재시도를 안내한다. 중복 클릭·재시도에 따른 중복 접수를 방지한다.
- [ ] 신청 자료는 운영자만 열람할 수 있게 한다.
- [ ] 채널별 유입, 방향 선택 완료, 샘플 확인, 상담 접수를 집계한다.
- [ ] 내부 시험 신청과 운영자 방문은 실제 모집 실적과 구분한다.
- [ ] 연락처와 자유서술은 URL이나 분석 이벤트에 넣지 않는다.
- [ ] 실제 수집 항목·보관 방식에 맞는 안내를 신청 화면에 연결한다.
- [ ] 성공·저장 실패·중복 제출·운영자 열람을 실제 저장 경로로 확인한다.

접수 후 안내에는 운영자가 지킬 수 있는 회신 시간을 기재한다. 네트워크 전송만 시작한 상태, 브라우저에만 저장한 상태, 메일 앱만 열린 상태를 접수 성공으로 처리하지 않는다.

완료 기준은 시험 신청 한 건이 저장되고 운영자가 확인해 회신할 수 있으며, 실패한 신청은 성공으로 표시되지 않는 것이다.

### 세 번째 단계는 모집과 유료 운영 준비

신청 기능을 검증한 뒤 모집 글과 링크를 준비한다. AI 전사 도구 검증과 운영 준비는 앞선 화면 개발과 병행한다.

- [ ] 접근 가능한 커뮤니티·SNS 중 초기 채널 한두 곳을 정하고 게시 규칙을 확인한다.
- [ ] 채널별 유입을 구분할 링크와 첫 모집 글을 준비한다.
- [ ] 상담에서 부모님 참여 의향, 일정, 코칭 역할에 대한 기대를 확인한다.
- [ ] 결제 수단, 결제 확인, 취소·일정 변경 대응과 코칭 제공 범위를 안내할 수 있게 한다.
- [ ] AI 전사 도구의 처리 위치, 학습 사용 여부, 보관 기간, 삭제 방식, 접근 보호를 확인한다.
- [ ] 녹음 당사자에게 처리 방식을 설명하고 동의를 확인하는 절차를 준비한다.
- [ ] 동의받은 시험 녹음으로 전사 품질과 검수 시간을 확인한다.
- [ ] 녹음 전달과 전사본 제공에는 접근이 제한된 경로를 사용한다.
- [ ] 유료 5가구의 실제 결제와 코칭 시작 여부를 기록한다.

전사 도구와 자료 처리 조건을 확인하기 전에는 실제 녹음을 외부 AI에 전달하지 않는다. AI 전사 동의를 샘플 공개나 요약·원고화 동의로 대신하지 않는다. 외부 게시와 배포는 준비된 결과를 검토한 뒤 진행한다.

## 최소 운영대장과 지표

신청별로 유입 채널, 방향 선택값, 연락 수단, 상담 상태, 부모님 참여 준비, 다음 일정, 실제 결제, 취소·환불, 작업 시간을 기록한다. 연락처와 상담 내용은 비공개 운영 자료로 관리한다.

| 지표 | 측정 방식 |
| --- | --- |
| 샘플 도달 | 같은 집계 기간과 방문 단위로 방향 선택 시작 대비 샘플 확인을 집계 |
| 상담 전환 | 샘플 확인 대비 실제 저장된 상담 신청, 반복 이벤트와 중복 접수 구분 |
| 결제 전환 | 상담 진행 건 대비 확인된 결제, 취소·환불 별도 기록 |
| 완주 | 5가구 중 4가구 이상이 가구별 시작일부터 8주 안에 인터뷰 2회 완료 |
| 코칭 가치 | 5명 중 4명 이상이 혼자였다면 완주하지 못했을 것이라고 응답하는지 확인 |
| 운영 부담 | 결제 전 상담, 질문 설계, 일정 조율, 피드백, 전사 검수의 실제 시간 기록 |
| 책 제작 | 관심 표현과 실제 추가 결제를 구분 |

목표 전환율과 가구당 허용 공수는 아직 확정하지 않았다. 기존 설문의 구매 의향을 현재 웹 전환율이나 코칭 상품의 유료 수요로 간주하지 않는다. 실제 비용에는 미결제 상담에 든 시간도 포함해 판단한다.

## 현재 사이트에서 전환할 부분

`index.html`의 무료 가족 앱 소개·메타 정보와 `partials/`의 메뉴·안내를 코칭 시안으로 교체했다. `src/main.js`에는 방향 선택, 샘플 표시, 검증, 상담 초안 확인을 구현했다. 실제 접수 처리는 다음 단계다.

이전 앱의 `privacy.html`, `terms.html`, `support.html`과 전용 공용 조각·이미지 자산은 제거했다. 상담 데이터와 녹음 처리 방식이 정해지면 코칭용 안내와 정책을 작성한다. 이전 앱의 조건을 새 서비스에 그대로 적용하지 않는다.

코칭 서비스 공개 시 실제 도메인, 호스팅, 안내 문서, 신청 저장, 메타 정보, 모바일 동작을 기준으로 배포 완료 조건을 정한다. 기존 앱의 배포 절차는 사용자 요청에 따라 폐기했다. 근거는 [docs/work/W-003-main-obsolete-docs.md](work/W-003-main-obsolete-docs.md)에 기록한다.

## 바로 시작할 작업

구현한 네 화면을 검토하고 상담 저장소·운영자 확인·회신 경로를 결정한다. 실제 신청 저장과 오류 처리를 연결해 모집 가능한 버전으로 만든다. AI 전사 운영 준비는 이 작업과 병행한다.
